> Nit: maybe a gdprintk() here, so the caller can tell why the request

When the hypercall handlers return EINVAL, the domain builder code
in the toolstack can log the invalid arguments of the failing call.

Toolstack developers can then fix the domain builder. A toolstack
developer will have to debug the root cause of the invalid request
in his code base, and from looking at the logged claim request, the
cause should be obvious. v8 will also have a detailed API spec that
lists all the possible causes for each errno returned, so toolstack
developers can refer to it in case their claim hypercalls fail.
You'll find this API documentation in the v8 submission.

-> Obsoleted:

When offlining free memory, e.g. using XEN_SYSCTL_page_offline_op,
free memory can drop below the pools of claims. In this corner case,
I tried to release claims in this case in v7, but due to feedback,
v8 no longer does that, which is a lot better.

v8 handles this corner case as something that can be the case, which
is much easier, and this removes a lot of added code and this comment.

I updated the chapter about this case in the v8 design docs:
https://xen.kaindl.dev/claims-docs-v8/designs/claims/implementation.html#offlining-memory-in-presence-of-claims
